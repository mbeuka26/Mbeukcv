MbeukCV · deux applications · un Hub à part

Guide de déploiement

Ordre réel pour mettre en ligne MbeukCV Pro et MbeukCV SaaS. Aucune clé n’est écrite dans cette page. Les cases se souviennent dans ce navigateur seulement, pour suivre la checklist.

1. Ordre

Deux produits coexistent. Ils ne partagent pas la même base ni le même stockage.

  1. MbeukCV Pro (mbeukcv-pro-v2) peut être publié seul. Sans Supabase, il reste un poste local : CV dans le navigateur, clé Claude saisie sur l’appareil.
  2. Supabase Pro est optionnel. Il sert aux crédits, à l’e-mail, au matching et aux clés de collecte. Ce n’est pas le Hub.
  3. MbeukCV SaaS (mbeukcv-saas) est l’application Cloud, prévue pour Vercel, avec sa propre base Supabase.
  4. Le Hub (licence, paiement, entitlement) reste un service séparé. On ne déploie pas les CV dans le Hub, et on ne met pas ses secrets dans le navigateur.
Ne jamais publier SUPABASE_SERVICE_ROLE_KEY, ENCRYPTION_KEY, MBEUK_AUTH_BRIDGE_SECRET, CREDIT_GRANT_SECRET ni une clé sk-ant- dans une variable NEXT_PUBLIC_ ou VITE_. Ces préfixes arrivent dans le navigateur.

2. Publier MbeukCV Pro

Répertoire : mbeukcv-pro-v2. La navigation est en hash (#/parametres), ce qui permet un hébergement de fichiers statiques.

Build servi en HTTPS

C’est le mode à utiliser dès qu’un dossier de récupération ou une PWA est attendu. Le choix de dossier et le service worker exigent une origine sécurisée. Un fichier ouvert en double-clic (file://) ne le permet pas.

cd mbeukcv-pro-v2
npm install
npm test
npm run build

Le résultat est le dossier dist/. Placez-le derrière HTTPS (Vercel, Netlify, nginx, ou l’hébergement statique déjà utilisé). Toutes les routes reviennent sur index.html : avec le hash, aucune réécriture serveur n’est obligatoire.

Fichier autonome

npm run build:standalone

Le résultat est dist-standalone/index.html. Aucune clé n’est injectée au build. Ce mode sert de copie portable. Le dossier surveillé n’y fonctionne pas. L’export « Emporter une copie » reste le chemin de sortie des données.

Avant de considérer Pro en ligne

3. Supabase Pro, seulement si les crédits sont voulus

Sans URL dans Paramètres, Pro ne contacte pas cette base. Le détail opérationnel est dans mbeukcv-pro-v2/supabase/README.md. Résumé à suivre dans l’ordre.

  1. Créer un projet Supabase distinct de celui du SaaS.
  2. Activer Authentication → Anonymous Sign-ins.
  3. Exécuter mbeukcv-pro-v2/supabase/schema.sql dans le SQL Editor. Ne pas ajouter de DROP ni de TRUNCATE.
  4. Créer une licence réelle dans public.licences. Le code d’exemple du README n’est pas une licence de production.
  5. Déployer les fonctions :
supabase functions deploy generate-docs
supabase functions deploy send-application
supabase functions deploy scrape-offers --no-verify-jwt
supabase functions deploy collect-offers
supabase functions deploy source-keys
supabase functions deploy refresh-matches

scrape-offers n’est pas appelée par l’écran. Elle n’accepte que l’en-tête x-cron-secret égal à SCRAPE_CRON_SECRET. Sans ce secret, la réponse est 401.

Secrets de fonction, posés sur Supabase, pas dans Git

supabase secrets set MASTER_CLAUDE_KEY=...
supabase secrets set BREVO_API_KEY=...
supabase secrets set BREVO_FROM_EMAIL=...
supabase secrets set BREVO_FROM_NAME="MbeukCV Pro"
supabase secrets set SCRAPE_CRON_SECRET=...
supabase secrets set JSEARCH_API_KEY=...
supabase secrets set COLLECT_KEYS_KEY=...

AFRICAWORK_API_URL et AFRICAWORK_API_KEY ne se posent que si Africawork a fourni une adresse réelle.

COLLECT_KEYS_KEY doit faire au moins 16 caractères. Tant qu’elle est absente, les clés JSearch et Africawork restent en clair dans cles_collecte.secret. Avec elle, les nouvelles écritures sont chiffrées. Le client ne lit pas cette table : aucune policy ne l’y autorise.

Dans Paramètres de l’application, saisir uniquement l’URL du projet et la clé anon. Jamais la clé service.

Le cron quotidien est le bloc SQL de la section 7 du README Supabase Pro. Remplacez la référence du projet et la valeur de SCRAPE_CRON_SECRET. pg_cron et pg_net doivent être activés.

4. Google Drive, optionnel

Le bouton Drive n’apparaît que si le build Pro contient VITE_GOOGLE_CLIENT_ID. C’est l’identifiant OAuth public du projet Google, pas un secret de serveur.

  1. Dans Google Cloud, créer un client OAuth de type application Web.
  2. Autoriser l’origine HTTPS exacte de Pro, et http://localhost:5173 seulement pour les essais.
  3. Le scope utilisé par l’application est https://www.googleapis.com/auth/drive.file. Elle ne demande pas l’accès à tout le Drive.
  4. Sous PowerShell, avant le build : $env:VITE_GOOGLE_CLIENT_ID="identifiant-public" puis npm run build.

Après un effacement des données du navigateur, Drive ne revient seul que si la session Google de ce navigateur existe encore. Sinon, l’utilisateur choisit à nouveau le dossier MbeukCV, ou importe le fichier .mbeukpack.

5. Publier MbeukCV SaaS avec le workflow

Le déploiement en ligne de SaaS n’est pas une saisie manuelle dans Vercel. Le fichier mbeukcv-saas/.github/workflows/deploy.yml le fait. Le guide pas à pas, avec les trois tableaux de secrets, est mbeukcv-saas/docs/deploiement.html.

Vous tapez ceci, puis GitHub publie Supabase et Vercel :

cd "C:\Users\NATEIVA DOUALA\MBEUKSAAS\mbeukcv\mbeukcv-saas"
npm run security
npm test
git push -u origin main

Le job vert dépose les secrets Edge, déploie les fonctions de supabase/edge-functions, dépose les variables de production Vercel, puis publie le site. Il ne déploie pas Pro. Les migrations SQL restent manuelles.

Répertoire : mbeukcv-saas. Next.js 14. Le fichier vercel.json déclare deux tâches : /api/cron/scrape à 04:00 UTC et /api/cron/cleanup à 23:00 UTC. Vercel envoie Authorization: Bearer avec CRON_SECRET, que le workflow a déposé.

La base SaaS est un autre projet Supabase que celui de Pro. Le schéma est mbeukcv-saas/supabase/schema.sql, plus les migrations déjà présentes dans supabase/migrations/ si elles ne sont pas encore appliquées sur ce projet. Ne pas fusionner les deux schémas. Ne pas activer l’écriture client des colonnes supabase_service_role_key, claude_api_key ou rapidapi_key de user_profiles : le code applicatif ne les utilise pas.

Le Hub reste https://mbeukhub.vercel.app sauf décision contraire. MBEUK_PRODUCT_ID, MBEUK_APPLICATION_ID et MBEUK_HUB_API_KEY viennent du portail Hub. Aucune clé Chariow ne se place dans ce dépôt : le paiement passe par le Hub.

7. Contrôle après mise en ligne

Le SaaS a un workflow : mbeukcv-saas/.github/workflows/deploy.yml. Pro n’en a pas. Le test Pro ne contacte pas une base, sauf si MBEUK_TEST_DATABASE_URL est défini pour supabase/tests/check-revokes.sql.

8. Limites à connaître avant de promettre le service

  • Effacer les données du site retire la permission du dossier. Le navigateur ne peut pas le rouvrir seul. Drive revient sans clic seulement si la session Google est encore ouverte.
  • Sur iPhone, un dossier surveillé en continu n’est en général pas disponible. Le fichier exporté, gardé dans Fichiers, est le chemin prévu.
  • navigator.storage.persist() réduit le risque d’effacement sous pression disque. Ce n’est pas une copie de secours.
  • La clé Claude de travail de Pro reste lisible par une extension de la même origine. La copie qui sort du navigateur est chiffrée.
  • Perdre ENCRYPTION_KEY du SaaS rend illisibles les clés Claude déjà enregistrées dans les comptes. Il n’existe pas de réparation côté client.
  • La synchronisation Cloud des CV classiques Pro n’est pas en place. Le mode hub et le mode local ne fusionnent pas les deux historiques.

9. Retour arrière

Pro : retirer la publication du dossier dist/ et republier le build précédent. Les CV déjà dans les navigateurs restent dans IndexedDB. Les fichiers MbeukCV déjà écrits sur les postes restent sur les postes.

SaaS : dans Vercel, promouvoir le déploiement précédent. Ne pas changer ENCRYPTION_KEY pendant ce retour : les clés déjà chiffrées avec l’ancienne valeur ne se liront plus.

Supabase : ne pas lancer de script qui supprime licences, historique_cv, cles_collecte ou user_profiles pour « repartir propre ». Une correction de schéma se fait par ajout, après copie de sauvegarde du projet.

Document produit pour le dépôt MbeukCV. Il décrit le déploiement. Il ne remplace pas un essai sur l’adresse publique.
